# 代谢与心血管 Skills：纵向管理及 App 接入要求

讨论稿，2026-09-30。本文件是代谢类和心血管类两个 Skill 的共同产品要求，与各自疾病指标目录配套。两个 Skill 都面向同一患者随时间积累的资料，支持长期管理。本文件尚未代表 App 已实现这些行为或临床规则已经获批。

每个疾病模块都要说明哪些资料属于诊断档案，哪些属于重复测量，哪些属于事件，以及这些资料怎样影响后续解释。遗传报告和确诊依据保留历史版本；化验、生命体征和功能评估按时间追加；用药启停、剂量调整、症状发作、住院、手术和随访按事件保存。检查计划、检查完成和结果回报分别记录。某项资料不需要反复检测，也仍然属于患者纵向档案。

App 负责保存患者资料和可追溯的历史。新增结果不能覆盖旧结果。纠错或撤回需要保留原记录及更正关系，并确保失效记录不再参与当前分析。同一患者的同一测量只保存一次，由代谢、心血管和其他相关模块读取。Skill 文件保存通用知识和解释规则，不保存实际患者病历，也不依赖聊天记忆维持患者历史。

每条测量应携带患者关联、记录标识、指标名称、原值、原单位、标本、来源、测量方法、实际测量时间和相关情境。录入时间、文书时间及事件发生时间分开保存。时间只有日期、只有月份或完全未知时，保留原有精度，不补造具体时刻。单位、空腹状态、设备或治疗情境缺失时，明确标记未知。来源不同但疑似重复的记录先核对，不能重复计为趋势中的两个时点。

调用 Skill 时，App 应提供本次评估时点、此次新增或更正的记录、相关历史窗口、既有诊断和治疗事件，以及当前个体目标与随访计划。历史资料未完整提供时，明确返回可用范围。回顾某个历史时点时，只使用当时已经可获得的资料，避免用后来的诊断或结果解释过去。具体接口、存储方式和窗口长度在接入 App 时确定，不在本文件中假定已经实现。

分析趋势前，先检查是否属于同一指标、同类标本，以及测量方法、单位和情境是否可比较。允许换算时保留原值、转换依据和转换结果。每次趋势输出注明观察窗口、有效记录数、实际时间跨度及比较依据。两次可比较的结果可以描述前后差异；“持续升高”“长期稳定”等结论还需要专病规则定义足够的观察时间和数据覆盖，不能仅凭任意两次结果成立。

个人基线、医生给出的目标和诊断阈值分别保存。目标和治疗方案需要生效时间及来源；历史结果依当时适用的目标解释。测量应关联治疗调整、急性疾病和住院等背景，以说明前后变化发生在什么条件下。时间上的先后关系只能支持描述关联，不能自动认定某项药物导致改善或恶化。

只有一个有效时点时，输出单次结果及纵向资料不足。没有新记录时，返回最后可用结果的日期和数据缺口，不默认病情稳定、结果正常或检查未完成。随访是否到期需依据医生计划或已审核的专病规则，并检查计划生效日期与完成状态。提醒需要在新结果、计划变更和问题解决后更新，避免重复发送。急性风险按单独审核的安全规则处理，不以先积累长期趋势为前提。

Skill 返回 App 的内容应包含评估时点、所用记录及日期、可比较的趋势、当前状态、相关治疗或临床事件、缺失资料和下一步提示。每项判断携带适用疾病、规则版本和数据依据；无法判断时说明具体缺口。App 合并两个 Skill 对同一检查或随访的重复提醒，并保留解释冲突供审核。新的临床确诊、分型澄清或风险状态变化作为带依据和时间的更新，不抹去既往状态，也不由 Skill 擅自写入确诊。

代谢 Skill 应按疾病读取适用的血糖、HbA1c、体重、血脂及其他指标历史，并关联营养与治疗记录。心血管 Skill 应按疾病读取适用的血压、心率、体重、功能评估、影像和事件历史。共用字段来自同一数据记录，疾病解释和观察窗口由各自已审核规则确定。目录中的全部检查不构成每位患者都要定期完成的统一检查套餐。

接入验收需要使用合成的连续病例序列，覆盖单次结果、重复记录、日期缺失、乱序录入、单位或设备变化、长期缺测、目标变更、治疗调整、记录更正、多病共存及提醒完成后的状态更新。检查历史不被覆盖、不可比结果不被拼成趋势、未来资料不泄漏到历史评估，以及输出能追溯到相应记录。具体数值阈值、时间窗口、复查频率和自动预警均须另行完成专病审核。

目前代谢病本地核对主要验证具有疾病依据的同次住院内的预设字段覆盖，尚未系统验证跨次就诊的连续轨迹。心血管字段核对和补充病例也不等于各病已完成纵向验证。后续评估需要另报可用时间点、随访跨度、缺失情况和跨次就诊关联质量；每病抽取 50 人的目标本身不能证明纵向管理有效。
